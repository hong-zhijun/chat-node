# 私聊聊天服务 - 开发说明

> 给开发者的完整规格说明。按本文档实现即可。

---

## 一、项目概述

基于 Node.js 的私聊聊天服务，主要功能：

- 一对一私聊（文字消息、图片消息）
- 独立的文件共享模块（与聊天分离）
- 多设备登录（同一账号可同时登录多端，消息实时同步）
- 后台管理（用户管理、手动清理消息和文件）
- 模仿 ChatGPT 风格的聊天界面，PC + 移动端均适配
- 长连接稳定可靠：心跳、自动重连、断线消息补发、发送队列、连接状态可视化

私有部署，不公开使用。

## 二、技术栈（追求简单稳定）

| 用途 | 选型 | 说明 |
|------|------|------|
| 运行时 | Node.js 18+ | LTS 版本 |
| Web 框架 | Express | 生态最广，稳定 |

| 鉴权 | `jsonwebtoken` | JWT |
| 文件上传 | `multer` | 标准 multipart 处理 |
| 图片缩略图 | `sharp` | 服务端图片处理 |
| ID 生成 | `uuid` | v4 |
| 前端 | Vue 3 + Vite | 简单易上手 |
| 前端 UI | Tailwind CSS | 跟着设计稿走即可 |

文件传输方式：**HTTP 上传/下载，不走 WebSocket**。WebSocket 只传文本指令和消息元数据，避免大文件阻塞实时消息。

## 六、鉴权流程

### 用户登录
- `POST /api/auth/login` body `{ loginKey, deviceLabel? }`
- 校验 login_key 存在且 status=1
- 生成 tokenId (UUID)，写入 sessions
- 签发 JWT，payload `{ userId, tokenId, type: 'user' }`，有效期 30 天
- 返回 `{ token, user: { userId, name } }`

### 管理员登录
- `POST /api/admin/login` body `{ adminKey }`
- 校验 adminKey 与配置一致
- 签发管理员 JWT，payload `{ type: 'admin' }`，有效期 7 天

### 鉴权中间件
- HTTP：从 `Authorization: Bearer <token>` 取
- WebSocket：从连接 URL query string `?token=xxx` 取
- 校验 JWT 签名 + 校验 sessions.revoked != 1
- 更新 sessions.last_active_at

### 注销
- `POST /api/auth/logout` 将当前 tokenId 在 sessions 表 revoked=1
- 服务端会主动关闭该 token 对应的所有 WebSocket 连接

### 多设备
- 同一 user 可同时有多个 token，互不影响
- 发送/接收消息时，服务端遍历该用户**所有在线连接**推送
- 自己 A 设备发的消息，B 设备也会收到（保持同步）

## 八、WebSocket 协议

### 连接
`ws://host/ws?token=<jwt>`

服务端校验：
- token 无效 → close code 4401
- 用户禁用 → close code 4403
- 通过后，将该连接登记到 `Map<userId, Set<WebSocket>>`

### 心跳与稳定性

1. **业务层心跳**
   - 客户端每 25s 发 `{type: "ping"}`，服务端回 `{type: "pong"}`
2. **传输层心跳**
   - 服务端每 25s 调用 `ws.ping()`；客户端 ws 库自动回 pong
3. **超时**
   - 服务端为每个连接维护 lastActiveAt（任何消息都刷新）；30s 没活动 → `ws.terminate()`
4. **客户端自动重连**
   - onclose 后按 1s → 2s → 4s → 8s → 16s → 30s 指数退避
   - 立刻进入"重连中(第 N 次)"状态显示
5. **断线消息补发**
   - 客户端 localStorage 持久化 `lastReceivedMessageId`
   - 重连 onopen 成功后：
     1. HTTP GET `/api/messages/missed?afterId=<lastReceivedMessageId>` 拉取漏掉的消息
     2. 将本地未 ack 的消息队列重新通过 WS 发送
6. **发送队列**
   - 每条客户端发的消息生成 `clientMsgId` (UUID)
   - 存入 IndexedDB 待发队列，UI 显示"发送中"
   - 收到服务端 `ack` 后从队列移除并显示"已发送"
   - 服务端按 `client_msg_id` UNIQUE 实现幂等：5 分钟内重复的视为同一条，直接返回已存在的消息 ack
7. **连接状态**
   - 客户端 ConnectionState：`connected` / `connecting` / `reconnecting` / `disconnected`
   - 顶部状态指示器实时反映；disconnected 时显示"手动重连"按钮

### 客户端 → 服务端

```jsonc
// 心跳
{ "type": "ping" }

// 发文字
{
  "type": "send",
  "clientMsgId": "uuid",
  "to": "123456",
  "msgType": "text",
  "content": "hello"
}

// 发图片（先 HTTP 上传拿到 fileId，再发这个）
{
  "type": "send",
  "clientMsgId": "uuid",
  "to": "123456",
  "msgType": "image",
  "content": {
    "fileId": "...",
    "filename": "...",
    "size": 12345,
    "mime": "image/png",
    "width": 800,
    "height": 600
  }
}

// 发文件（聊天里也可以发，但用户更应该用文件共享）
{
  "type": "send",
  "clientMsgId": "uuid",
  "to": "123456",
  "msgType": "file",
  "content": { "fileId": "...", "filename": "...", "size": 12345, "mime": "..." }
}

// 撤回
{ "type": "recall", "messageId": 123 }

// 已读上报
{ "type": "read", "peerId": "123456", "lastMessageId": 123 }

// 正在输入
{ "type": "typing", "peerId": "123456" }
```

### 服务端 → 客户端

```jsonc
{ "type": "pong" }

// 收到消息（推给接收方所有设备 + 发送方除当前外的设备）
{
  "type": "message",
  "data": {
    "id": 123,
    "fromUserId": "111111",
    "toUserId": "222222",
    "type": "text",
    "content": "...",
    "createdAt": 1716000000000,
    "clientMsgId": "uuid"
  }
}

// 发送 ack（只回给发送方该连接）
{
  "type": "ack",
  "clientMsgId": "uuid",
  "messageId": 123,
  "createdAt": 1716000000000
}

// 撤回通知（推给对方和本人其他设备）
{ "type": "recall", "messageId": 123 }

// 已读通知（推给对方）
{ "type": "read", "peerId": "<本人userId>", "lastReadMessageId": 123 }

// 正在输入
{ "type": "typing", "peerId": "<对方userId>" }

// 在线状态（可选：对方上下线时推一次）
{ "type": "presence", "userId": "...", "online": true }

// 错误
{ "type": "error", "code": "...", "message": "..." }
```

### 推送目标规则
- 发文字/图片/文件成功后：
  - 推 `message` 给 `to_user_id` 所有连接
  - 推 `message` 给 `from_user_id` 除当前发起连接外的所有连接（多端同步）
  - 推 `ack` 给当前发起连接

## 九、消息撤回

- 仅 `from_user_id == 自己` 的消息
- 仅 `now - createdAt <= 2 分钟`
- 撤回操作：`UPDATE messages SET recalled=1 WHERE id=?`
- 推送 `recall` 给对方所有连接 + 自己其他连接
- 前端展示："This message was recalled" 灰色斜体；原内容不展示，但 DB 保留

## 十、文件共享模块

独立于聊天的功能模块：

- 所有登录用户均可上传到共享区
- 所有登录用户均可查看列表、下载
- 删除：仅上传者或管理员
- 与聊天附件物理分离（`uploads/chat` vs `uploads/share`），便于分别清理
- 文件名重复不覆盖（用 fileId 做磁盘文件名，原文件名仅用于显示与下载时的 Content-Disposition）

## 十一、图片消息处理

1. 客户端选图 → HTTP POST `/api/files/upload?scope=chat`
2. 服务端 multer 接收 → sharp 生成缩略图（长边 400px，jpeg quality 70）→ 写 `<fileId>.thumb.jpg`
3. 返回 `{ fileId, width, height, hasThumbnail: true, ... }`
4. 客户端 WS 发 `{type: "send", msgType: "image", content: {fileId, ...}}`
5. 接收端聊天气泡内 `<img>` 加载 `/api/files/:fileId/thumbnail`
6. 点击 → 全屏查看器加载 `/api/files/:fileId` 原图，支持手势缩放、下载、ESC/点击外部关闭

## 十二、管理后台

### 概览
四个统计卡片：
- 当前在线连接数（WS 连接数，按 userId 去重）
- 总用户数
- 总消息数
- 存储占用：聊天附件 / 共享区 / 合计

### 用户管理
- 表格：user_id、name、login_key（默认 `••••••••`，点击眼睛图标显示）、status、created_at、操作
- 操作：禁用/启用切换、重置 login_key、改名、删除
- 「+ New User」按钮：弹窗输入 name（必填）+ 可选自定义 user_id（不填则自动生成 6 位数字，需校验唯一）+ 可选自定义 login_key（不填则自动生成 32 位随机串）
- 删除用户：二次确认；删除后该用户消息记录的处理策略：保留消息但显示"[Deleted User]"（或物理删除，由实现决定，**推荐物理删除连同其消息**）

### 清理
两个 tab：

**消息清理**
- 表单：日期选择器（清理早于此日期的消息）+ 可选用户筛选（清理某用户的所有消息）
- 「Preview」按钮 → 显示将被删除的数量
- 「Confirm Delete」红色按钮 → 二次确认 → 执行

**文件清理**
- 表单：
  - 早于某日期（可选）
  - 大于 N MB（可选）
  - 范围多选：chat / share
- 「Preview」→ 列出将被删除的文件（数量 + 总大小，可展开看明细）
- 「Confirm Delete」→ 执行：
  1. 删除磁盘文件 + 缩略图
  2. 删除 files 表记录
  3. 对于 chat 范围的，将引用了这些 file_id 的消息的 content 改为占位标记 `{"deleted": true, "filename": "..."}`，前端展示"文件已被管理员清理"

- 主题（localStorage）

### 连接状态指示器
顶部右侧小圆点 + 文字（hover/点击展开）：

3. 提示去 `config.js` 设置 adminKey 和 jwtSecret

## 十五、安全注意事项

- adminKey 和 jwtSecret 必须修改为强随机字符串
- 上传文件不可用原文件名做磁盘名（防路径穿越），用 fileId
- 下载接口需鉴权，且校验 scope=chat 时的对话归属
- 用户输入做转义（消息内容由前端展示时转义，DB 存原文）
- SQL 全部使用参数化查询（better-sqlite3 prepared statement）
- 部署时建议放在 Nginx/Caddy 后做 HTTPS
